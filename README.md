# audisp-strace

**Linux Audit Event Consumer & `strace`-like Trace Formatter**

`audisp-strace` translates raw Linux audit records into clear, human-readable system call traces modeled after [`strace`](https://strace.io/), enriched with **full process ancestry trees** and **comprehensive process credentials**.

It operates as an **`audisp` plugin**, as a **live stream monitor** on `/var/log/audit/audit.log`, or as an **offline forensic tool** for analyzing past audit logs.

```text
29381<test_syscalls> 14:23:01.123 openat(AT_FDCWD</tmp>, "config.json", O_RDONLY|O_CLOEXEC) = 3</tmp/config.json>
    uid=1000 (sorenson), gid=1000 (sorenson), auid=1000 (sorenson), agid=1000 (sorenson), euid=1000 (sorenson), egid=1000 (sorenson)
    1 (systemd) -> 29380 (bash) -> 29381 (test_syscalls)
```

---

## Why audisp-strace?

Standard Linux audit records (`/var/log/audit/audit.log`) capture system activity system-wide with near-zero overhead, but reading them raw is notoriously difficult:
- A single system call is split across multiple separate records (`SYSCALL`, `CWD`, `PATH`, `PROCTITLE`, `EXECVE`, `SOCKADDR`).
- File paths and command lines are often hex-encoded (`74657374...`).
- Process information only records `<pid>` and immediate `<ppid>`, offering no insight into whether a process was spawned by a cron job, a shell session, an SSH login, or a system daemon.
- Standard `strace` cannot run in production 24/7 without severe `ptrace` latency and cannot capture short-lived processes retroactively.

`audisp-strace` bridges this gap: it correlates audit records in real time, tracks process state and file descriptors across `clone`, `fork`, `execve`, and `close`, and formats output like `strace` while exposing the security context of every call.

## Features

- **Rich 3-Line Output**:
  - **Line 1 (Trace)**: `<pid><comm> timestamp syscall(args) = result`
  - **Line 2 (Credentials)**: Process identities (`uid`, `gid`, `auid`, `agid`, `euid`, `egid`, `suid`, `sgid`, `fsuid`, `fsgid`) with username and group resolution.
  - **Line 3 (Ancestry)**: Full process hierarchy walk (`1 (systemd) -> ... -> parent (comm) -> child (comm)`).
- **Compact 1-Line Mode (`-C` / `--compact`)**:
  - Single-line format per event with inline `[uid=...]` and `[ppid:...]` tags for high-throughput terminal monitoring or piping to `grep`/`awk`.
- **Structured JSON Lines Output (`--json` / `--jsonl`)**:
  - Output each audit event as a machine-readable JSON object containing full syscall details, errno, resolved paths, credential dictionary, and process ancestry array for SIEM and log ingestion (`jq`, Vector, Loki, Elasticsearch).
- **Extensive Syscall Coverage (285+ syscalls)**:
  - File I/O, lifecycle, descriptors, permissions, attributes, and ownership.
  - Sockets & networking with binary hex `SOCKADDR` decoding (IPv4, IPv6, UNIX sockets [filesystem, abstract `@`, unnamed], Netlink, Packet, VSOCK).
  - Modern Linux syscalls: `openat2`, `close_range`, `statx`, `statmount`, `listmount`, `futex_waitv`, `pidfd_*`, `io_uring_*`, `landlock_*`, `process_madvise`, and more.
- **`strace`-Compatible & Custom `%CLASS` Selectors**:
  - **Filesystem Investigation Classes**:
    - `%perm` (or `%perms`): Permission, ownership, attribute, and ACL modifications (`chmod`, `chown`, `setfacl`/`*xattr`, `file_setattr`).
    - `%remove` (or `%delete`): File and directory deletions and renames (`unlink`, `unlinkat`, `rmdir`, `rename`, `renameat`, `renameat2`).
    - `%mount` (or `%mounts`, `%mnt`): Mounts, unmounts, mount API operations, filesystem namespaces, and chroot (`mount`, `umount`, `umount2`, `pivot_root`, `chroot`, `fsopen`, `fspick`, `fsconfig`, `fsmount`, `move_mount`, `open_tree`, `open_tree_attr`, `mount_setattr`, `statmount`, `listmount`, `unshare`, `setns`, `swapon`, `swapoff`).
    - `%locks` (or `%lock`): File and record locking operations (`flock`, and `fcntl` with `F_SETLK`, `F_SETLKW`, `F_GETLK`, 64-bit variants, and Open File Description `F_OFD_*` locks).
  - **Standard Categories**: `%desc`, `%file`, `%net`, `%creds`, `%process`, `%memory`, `%signal`, `%ipc`, `%clock`, `%stat`, `%fstat`, `%%stat`, `%statfs`, `%fstatfs`, `%%statfs`, `%pure`.
- **Granular Filtering**:
  - Filter by PID (`-p`, `--exclude-pid`) with child process tracking (`-f` / `--follow-fork`).
  - Automatic Self-PID Quashing: Automatically quashes events generated by `audisp-strace` itself in live mode to prevent runaway audit feedback loops (override with `--trace-self`).
  - Filter by User or UID (`-u`, `--exclude-user`) matching real and effective identities.
  - Filter by Audit Login UID (`--auid`).
  - Filter by Login Session ID (`--session-id` / `--sid`, `--exclude-session-id` / `--exclude-sid`) to isolate specific user sessions or exclude unset background daemon sessions.
  - Filter by Process Command Name (`--comm`, `--exclude-comm`) and Executable Binary (`--exe`, `--exclude-exe`) with wildcard/glob matching.
  - Filter by Path Prefix (`-P` / `--path`, `--exclude-path`): Trace only syscalls accessing files under a directory or file prefix (modeled after `strace -P`), with automatic resolution of relative paths (`cwd`, `dirfd`), descriptors, and UNIX sockets.
  - Filter by Exit Status: failed only (`-Z`) or successful only (`-z`).
  - Targeted Error Code Filtering (`-e` / `--errno`, `-E` / `--exclude-errno`): Filter or exclude specific error names (e.g. `EACCES`, `ENOENT`, `perm`) or numeric error codes (e.g. `13`, `2`). Comma-separated or repeatable. Compatible with summary statistics (`-c`) and JSON output (`--json`).
- **Syscall Statistics & Summary (`-c` / `--summary-only`, `--summary`, `-S`)**:
  - Aggregates call counts, error counts, and error percentages per syscall.
  - Sortable by `calls`, `errors`, `error%`, or `name`.
- **ANSI Terminal Colorization (`--color=auto|always|never`)**:
  - Auto-detects TTY and respects `NO_COLOR`.
  - Color-codes PIDs, commands, timestamps, string literals, resolved FD paths, green success codes, and bold red errors.
- **String Length Limits (`-L` / `--string-limit` / `--strsize`)**:
  - Modeled after `strace -s strsize` (default: 32 characters, use 0 for unlimited) to prevent unwieldy multi-line string or argument dumps while keeping full pathnames intact.
- **Audit Key & Serial Display (`-k` / `--show-key`, `--show-serial`)**:
  - Displays audit rule keys (`[key="rule_name"]`) and event serial numbers (`14:19:27.079:1260437`) for immediate cross-correlation with `ausearch -a <serial>`.
- **Automatic State Garbage Collection & Bounded Memory (`--max-procs`)**:
  - Automatically reclaims finished process trees on process exit while retaining ancestors for active children.
  - Periodic background dead process sweep in live mode.
  - LRU capacity eviction (default: 10,000 processes, configurable via `--max-procs`) ensures strict memory bounds for indefinite production daemon operation.
- **Audit Log Follow Mode (`-F` / `--follow`)**:
  - Live continuous monitoring directly from `/var/log/audit/audit.log` (or any custom log file) without requiring `audispd` plugin daemon setup.
  - Built-in rotation tracking across inodes (e.g. `audit.log` rotated to `audit.log.1`), partial writes at EOF, and file truncations.
  - Supports `--from-start` (read whole file first) and `-n K` / `--lines K` (output last K lines before following).
- **Unlinked-While-Open / 'Ghost File' Tracking**:
  - Automatically identifies and annotates open file descriptors whose target file has been deleted/unlinked (`3</path/to/file (deleted)>`), mirroring `strace` behavior.
  - **In Live Mode**: Authoritative real-time detection via `/proc/<pid>/fd/<fd>` resolution and VFS unhashed dentry status.
  - **In Offline Mode**: Best-effort cross-process state correlation linking `open` and `unlink`/`unlinkat`/`rmdir` events by normalized path and `(device, inode)` pairs across forks and descriptor duplicates (`dup`, `dup2`, `dup3`, `fcntl`).
- **Output Compression & Flexible Redirection (`-o` / `--output`, `-A` / `--append`, `--compress`, `--gzip`, `--compress-level`)**:
  - Route traces directly to a file or stdout with transparent compression (`gzip`, `bz2`, `xz`).
  - Auto-selects compression based on file extension (`-o trace.log.gz`, `-o trace.json.gz`), or via explicit `--compress gzip` / `--gzip`.
  - Uses low-overhead `compresslevel=1` by default (achieving 85–95% space reduction with minimal CPU usage) and flushes deterministically for real-time inspection with `zcat` / `zless` / `zgrep`.
  - Full RFC 1952 concatenated stream support with `-A` / `--append`, terminal protection check for unredirected stdout, and transparent on-the-fly decompression of input audit files (`.gz`, `.bz2`, `.xz`, or via magic bytes).
- **Readable Mode Bits & Symbolic Permissions (`0755 <rwxr-xr-x>`)**:
  - Automatically decodes octal file and directory mode bits into readable permission strings across `chmod`, `fchmod`, `fchmodat`, `open`, `openat`, `creat`, `mkdir`, `mkdirat`, `mknod`, `mknodat`, and `umask`.
  - Distinguishes SUID (`04755 <rwsr-xr-x>`), SGID (`02755 <rwxr-sr-x>`), Sticky (`01777 <rwxrwxrwt>`), and umask values (`0022 <----w--w->`, `0 <--------->`).
  - Resolves file type constants in `mknod` (`S_IFIFO|0644 <rw-r--r-->`) and System V IPC flags in `shmget`/`semget`/`msgget` (`IPC_CREAT|0600`).
- **Multi-File Chronological Merging (`-m` / `--merge`, `--sort-time`)**:
  - Automatically merges events across multiple audit logs or rotated file segments (`audit.log`, `audit.log.1.gz`, `audit.log.2.xz`) in strict chronological order using a streaming k-way merge.
  - Eliminates the need to manually sort or reorder files when analyzing multi-day incidents spanning across rotated log files.
- **Relative Timestamps (`-r` / `--relative-time`, `-t relative`, `--relative-by-pid`)**:
  - Displays elapsed time delta since the previous event modeled after `strace -r` with microsecond precision.
  - Standard `-r` appends relative deltas (`(+     0.001253)`) next to wall-clock timestamps, while `-t relative` displays standalone relative time (`     0.001253`).
  - Optional `--relative-by-pid` isolates deltas per process to track elapsed execution time within each PID independently.
  - Fully integrated with compact mode (`-C`), JSON output (`"relative_time": 0.001253`), and multi-file merging (`-m`).
- **Fast Time Range & Coverage Inspection (`--time-range`, `capinfos`-style)**:
  - Instantly inspects audit log files (<1ms via seek-based header/trailer reads on regular files, streaming on compressed files) to report start/end timestamps, duration, and serial ranges without full tracing.
- **SELinux AVC Awareness & Denial Highlighting (`--avc`, `-S avc`)**:
  - Automatically correlates kernel `type=AVC` and `type=USER_AVC` records sharing the event serial number.
  - Primary line annotation: tags enforcing denials with `[SELinux: DENIED { perms }]` (bold red) and permissive denials with `[SELinux: WOULD DENY { perms }]` (bold yellow warning).
  - Detailed context on Line 2b: outputs formatted `avc: scontext=... -> tcontext=... (tclass=..., permissive=1)` when an AVC record is present.
  - Streamlines credentials on Line 2: suppresses redundant identical UIDs/GIDs (`euid=suid=fsuid=uid`, `egid=sgid=fsgid=gid`, unset `auid`), leaving clean space for security contexts.
  - Enriched `mmap` formatting: parses `type=MMAP` records (`fd=...`) and cross-correlates file paths from attached AVC records, rendering `mmap(..., fd<path>, 0)`.
  - Dynamic `avc` column in `-c` summary table: automatically appears when AVCs are encountered, displaying per-syscall denial counts and supporting `-S avc` sorting.
  - Dedicated CLI filter: `--avc` / `--avc-only` / `--selinux` displays only events with SELinux decisions.
  - Supports multiple files (`audisp-strace --time-range /var/log/audit/audit.log*`) showing aligned per-file coverage and an overall Total span line.
  - Enriches summary mode (`-c` / `--summary`) to display boundary timestamps and duration above the syscall frequency table.
- **Audit Rule Generator (`--generate-rules` / `--auditctl`)**:
  - Automatically translates active CLI filters (`-s %perm`, `-s %mount`, `-P /etc`, `-u apache`, `-Z`) into exact, copy-pasteable `auditctl` shell scripts or `/etc/audit/rules.d/` rule files.
  - Handles safe syscall chunking, architecture matching (`-F arch=b64`), UID resolution, directory/path classification, session loop suppression, and teardown commands.

## Installation & Requirements

### Prerequisites
- Python 3.8+
- Python `auparse` bindings (Audit parsing library)

**On Fedora / RHEL / Rocky / CentOS**:
```bash
sudo dnf install audit-libs-python3 python3-audit
```

**On Debian / Ubuntu**:
```bash
sudo apt-get install python3-audit
```

### Installation
Clone the repository and install the script:
```bash
git clone https://github.com/username/audisp_strace.git
cd audisp_strace
chmod +x audisp-strace
sudo cp audisp-strace /usr/local/bin/
```

## Usage

```text
usage: audisp-strace [-F] [-s SYSCALLS] [-P PATHS] [-p PIDS] [-u USERS]
                     [-C] [-c] [-o OUT] [--json] [-h] [--help-all] [files ...]
```

Run `audisp-strace -h` for a concise, single-screen summary of common options, or `audisp-strace --help-all` for comprehensive help categorized by function.

### 1. Offline Audit Log Analysis

Analyze an existing audit log file:
```bash
audisp-strace --offline /var/log/audit/audit.log
```

Trace only file permission, ownership, and ACL modifications:
```bash
audisp-strace --offline audit.log -s %perm
```

Trace file and directory deletions or renames:
```bash
audisp-strace --offline audit.log -s %remove
```

Trace mount, unmount, and filesystem namespace activity:
```bash
audisp-strace --offline audit.log -s %mount
```

Trace file locking activity (flock and fcntl record/OFD locks):
```bash
audisp-strace --offline audit.log -s %locks
```

Trace system calls accessing files under `/etc` or `/var/www`:
```bash
audisp-strace --offline audit.log -P /etc,/var/www
```

Exclude background accesses to `/var/log`:
```bash
audisp-strace --offline audit.log --exclude-path /var/log
```

Display only failed system calls (`-Z`):
```bash
audisp-strace --offline audit.log -Z
```

### 2. Live Log Following (`-F` / `--follow`)

Follow the system audit log in real time (automatically tracks log file rotations across inodes):
```bash
sudo audisp-strace -F
```

Follow audit log and trace only permission or removal syscalls:
```bash
sudo audisp-strace -F -s %perm,%remove
```

Follow audit log and filter by accessed path prefix:
```bash
sudo audisp-strace -F -P /etc,/var/www
```

Follow audit log starting from the beginning of the file (rather than from the end):
```bash
sudo audisp-strace -F --from-start
```

Output the last 50 lines before following:
```bash
sudo audisp-strace -F -n 50
```

### 3. Live Monitoring via Pipe / audispd Plugin

Monitor audit events piped directly from `tail` or `audispd`:
```bash
sudo unbuffer tail -n0 -F /var/log/audit/audit.log | audisp-strace --live
```

Trace activity for a specific user and follow child processes:
```bash
sudo tail -n0 -F /var/log/audit/audit.log | audisp-strace --live -u user1 -f
```

Exclude background root noise:
```bash
sudo tail -n0 -F /var/log/audit/audit.log | audisp-strace --live --exclude-user root
```

### 3. As an `audisp` Plugin

`audisp-strace` can be configured directly inside auditd's dispatcher:

1. Copy the configuration file to the audit plugins directory:
   ```bash
   sudo cp audisp-strace.conf /etc/audit/plugins.d/
   ```
2. Restart `auditd`:
   ```bash
   sudo service auditd restart
   ```

When audit events are dispatched, `audisp-strace` automatically detects that its parent is `auditd`/`audispd` and enables live `/proc` lookups.

## Audit Sequence Gap & Drop Detection (`-g`, `--detect-drops`)

Linux audit events contain a monotonically increasing sequence counter (`msg=audit(timestamp:serial)`). When kernel audit buffers overflow or `auditd` rate-limits traffic, audit records are dropped.

`audisp-strace` can track event sequence continuity to detect and alert on lost audit records:

```bash
# Detect drops when following live audit logs
sudo audisp-strace -F --detect-drops

# Offline audit log verification with gap detection
audisp-strace --offline audit.log -g
```

When missing events are detected during tracing, a warning alert banner is displayed:
```text
*** AUDIT DROP DETECTED: 50 events lost (serials 8142572..8142621) ***
```

In JSON output mode (`--json`), structured drop events are emitted:
```json
{"event": "audit_drop", "timestamp": "2026-10-27T17:30:43.527560-05:00", "epoch": 1793140243.528, "dropped": 50, "start_serial": 8142572, "end_serial": 8142621}
```

In summary mode (`-c` / `--summary`), drop counts and gap instances are reported in the footer:
```text
-------  ---------  ---------  -------  ----------------
 100.00       3982         16     0.4%  total
-------  ---------  ---------  -------  ----------------
Audit drops: 0 events lost (stream continuous)
```

### Jitter Window & Threshold Tuning

On multi-core SMP systems under heavy load, Linux kernel netlink queues deliver events across CPUs with microsecond interleaving, causing minor out-of-order writes (typically within 10–130 serials). `audisp-strace` uses a sliding grace window (`--drop-window`, default `256`) to absorb out-of-order arrivals and ensure **zero false positives** on healthy logs.

| Option | Default | Description |
| :--- | :--- | :--- |
| `-g`, `--detect-drops` | Disabled | Enable audit sequence gap and drop detection |
| `--drop-threshold K` | `1` | Minimum number of lost events in a gap required to trigger an alert banner |
| `--drop-window N` | `256` | Sliding window size to absorb multi-core out-of-order delivery jitter |

## SELinux AVC Awareness & Denial Highlighting

When troubleshooting system issues, determining whether a permission failure was caused by standard UNIX file permissions (DAC) or an SELinux security policy decision (MAC) is often painful. Furthermore, in **Permissive mode**, syscalls succeed even though SELinux *would* have blocked them in Enforcing mode.

`audisp-strace` automatically correlates kernel `type=AVC` and `type=USER_AVC` records sharing the event timestamp and serial:

### 1. Enforcing Mode Denials
When SELinux blocks an operation, the primary syscall line is annotated with a bold red denial tag and the full source/target contexts are printed on Line 2b:
```text
2695136<ps> 10:25:16.083 openat(AT_FDCWD</var/lib/pcp>, "/proc/1313/environ", O_RDONLY) = -1 EACCES(Permission denied)  [SELinux: DENIED { perfmon, sys_admin }]
    uid=0 (root), gid=0 (root), auid=unset
    avc: scontext=system_u:system_r:pcp_pmlogger_t:s0 -> tcontext=system_u:system_r:pcp_pmlogger_t:s0 (tclass=capability2, capability)
    2695121 (unknown)->2695136 (ps)
```

### 2. Permissive Mode Warnings
When running in Permissive mode, the syscall returns success, but `audisp-strace` tags the line with a warning so latent breakage is immediately evident before switching to Enforcing:
```text
2855201<postdrop> 13:20:01.936 mmap(NULL, 688, PROT_READ, MAP_PRIVATE, 4</etc/centrifydc/group.ignore>, 0) = 0x7fee8c437000  [SELinux: WOULD DENY { map }]
    uid=0 (root), gid=0 (root), auid=unset, egid=90 (postdrop), sgid=90 (postdrop)
    avc: scontext=system_u:system_r:postfix_postdrop_t:s0-s0:c0.c1023 -> tcontext=system_u:object_r:etc_runtime_t:s0 (tclass=file, permissive=1)
    2855200 (unknown)->2855201 (postdrop)
```

### 3. Dedicated AVC Filtering & Summary Statistics
- Use `--avc` (or `--selinux`) to show only events with SELinux AVC records:
  ```bash
  audisp-strace --offline /var/log/audit/audit.log --avc
  ```
- Summary mode (`-c`) automatically includes an `avc` column whenever AVC records are encountered, and supports sorting by AVC frequency with `-S avc`:
  ```bash
  audisp-strace --offline audit.log -c -S avc
  ```

## Setting Up Audit Rules

To monitor syscalls with `audisp-strace`, the Linux kernel must be instructed to log syscall events using `auditctl`.

### Automatic Rule Generation with `--generate-rules`

The fastest and most reliable way to configure kernel audit rules matching your exact monitoring filters is using `--generate-rules` (or `--auditctl`). `audisp-strace` inspects your CLI arguments and generates an executable shell script with safe syscall batching, architecture tags (`-F arch=b64`), UID resolution, directory/path classification (`-F dir=` vs `-F path=`), session loop suppression, and teardown commands:

```bash
# Generate rules for file permissions changes under /etc and run directly:
audisp-strace --generate-rules -s %perm -P /etc | sudo sh

# Generate rules for network activity by a specific user:
audisp-strace --generate-rules -s %net -u apache | sudo sh

# Generate persistent rules for /etc/audit/rules.d/:
sudo audisp-strace --generate-rules -s %mount -o /etc/audit/rules.d/mounts.rules --rules-format file
sudo augenrules --load

# Remove generated rules when finished:
sudo auditctl -D -k "audisp_strace"
```

### Manual Configuration

Use the provided [`setup_audit_rules.sh`](file:///home/sorenson/projects/audisp_strace/setup_audit_rules.sh) script to set up monitoring rules with session exclusion (preventing audit storm loops when tailing logs over SSH):

```bash
# Add audit rules
sudo ./setup_audit_rules.sh

# Remove test audit rules
sudo ./setup_audit_rules.sh --delete
```

Or configure custom rules manually with `auditctl`:
```bash
# Example: monitor file permission and ownership changes
sudo auditctl -a always,exit -F arch=b64 -S chmod,fchmod,fchmodat -F key=perm_mod
sudo auditctl -a always,exit -F arch=b64 -S chown,fchown,lchown,fchownat -F key=perm_mod
```

## Architecture

`audisp-strace` is implemented as a single, self-contained Python executable structured into modular components:

- **`AuditEvent`**: Normalizes multi-record audit events (`SYSCALL`, `CWD`, `PATH`, `EXECVE`, `PROCTITLE`, `SOCKADDR`), cleans strings, and extracts exit codes.
- **`AuditDropDetector`**: Sequence analyzer tracking event serial numbers with sliding-window out-of-order jitter fulfillment and idle flush timers.
- **`ProcessTracker`**: In-memory state engine tracking parent/child relationships, command lines, current working directories, and file descriptors across fork/exec/close.
- **`ProcResolver`**: Fallback inspector resolving file descriptors and process info from `/proc` during live mode.
- **`SyscallHandler`**: Decodes arguments and formats syscall calls for over 285 distinct Linux syscalls.
- **`TraceFormatter`**: Handles timestamp variations (`time`, `datetime`, `epoch`), credentials formatting, compact tags, and process ancestry trees.
- **`ColorTheme`**: High-performance ANSI styling engine using token lexing to highlight paths, strings, and errors without delimiter conflicts.
- **`AudispStraceApp`**: Orchestrates `auparse` line un-wrapping, signal lifecycle (`SIGINT`, `SIGTERM`, `SIGPIPE`), filtering, and stream output.
